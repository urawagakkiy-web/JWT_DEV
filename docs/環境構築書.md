# 不動産管理アプリ 環境構築書

| 項目 | 内容 |
|---|---|
| アプリ名 | 不動産管理アプリ（real-estate-app） |
| リポジトリ | https://github.com/urawagakkiy-web/JWT_DEV |
| 作成日 | 2026-09-20 |
| 対象読者 | 本アプリをこれから動かす開発者 |

この手順どおりに進めれば、ローカルでアプリが動き、Vercel に公開するところまで到達できる。
所要時間はおよそ30分（Supabase のプロジェクト作成待ちを含む）。

---

## 1. 前提

### 1.1 必要なもの

| 種別 | 要件 | 確認コマンド |
|---|---|---|
| Node.js | 18以上（検証環境は 24.21.0） | `node -v` |
| npm | Node.js に同梱（検証環境は 11.19.0） | `npm -v` |
| Git | SSH鍵で GitHub に接続できること | `git --version` |
| ブラウザ | モダンブラウザ | — |

Node.js が未導入なら https://nodejs.org/ja から LTS 版を入れる。

### 1.2 必要なアカウント

- **Supabase** — https://supabase.com （無料枠で足りる）
- **Vercel** — https://vercel.com （公開する場合のみ）
- **GitHub** — リポジトリの取得に必要

---

## 2. リポジトリの取得

```bash
git clone git@github.com:urawagakkiy-web/JWT_DEV.git
cd JWT_DEV
```

HTTPS で取得する場合は `https://github.com/urawagakkiy-web/JWT_DEV.git` を使う。

---

## 3. 依存パッケージの取得

```bash
npm install
```

`package-lock.json` に記録されたバージョンがそのまま入る。
初回は数分かかることがある。`node_modules/` は Git 管理外。

---

## 4. Supabase プロジェクトの準備

### 4.1 プロジェクトを作る

1. https://supabase.com にログインし、**New project** を選ぶ
2. 名前（例: `realestate-app`）、データベースのパスワード、リージョン（`Northeast Asia (Tokyo)` など）を設定
3. 作成完了まで1〜2分待つ

> **データベースのパスワードは控えておくこと。** 再表示できない。

### 4.2 メール認証を有効にする

**Authentication → Providers → Email** を開き、有効になっていることを確認する。

研修や開発では **Confirm email をオフ**にしておくと、登録直後にそのままログインできて確認が早い。
オンのままでも動作するが、会員登録後に確認メールのリンクを開くまでログインできない。

### 4.3 接続情報を取得する

**Project Settings → API** から次の2つを控える。

| 項目 | 形式 |
|---|---|
| Project URL | `https://<project-ref>.supabase.co` |
| Publishable key | `sb_publishable_...` |

> **`service_role` キーは絶対に使わない。** RLS を無視できるキーで、
> ブラウザに配布されるフロントエンドに置いてはならない。

---

## 5. テーブルの作成

**Supabase ダッシュボード → SQL Editor** を開き、
リポジトリ内の [`supabase/schema.sql`](../supabase/schema.sql) の内容を貼り付けて **Run** する。

作られるもの:

- `properties` テーブル（物件名・家賃・エリア・間取り＋登録者）
- `updated_at` を自動更新するトリガー
- **RLS ポリシー4本**（自分が登録した物件のみ参照・登録・更新・削除できる）

成功すると `Success. No rows returned` と表示される。
同じ SQL を再実行しても既存データは消えない（`if not exists` で書いてある）。

### 確認

**Table Editor** に `properties` が現れ、テーブル名の横に **RLS enabled** と表示されていればよい。

---

## 6. 環境変数の設定

プロジェクト直下でひな形をコピーする。

```bash
cp .env.example .env
```

`.env` を開き、4.3 で控えた値に書き換える。

```
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

注意点:

- **`.env` は `.gitignore` で除外されている。** コミットしないこと
- **Vite は `VITE_` で始まる変数しかブラウザへ渡さない。** 名前を変えない
- **`.env` を書き換えたら開発サーバーを再起動する。** 起動中の変更は読み込まれない

---

## 7. 起動

### 方法A: ダブルクリック（macOS）

`起動.command` をダブルクリックする。
依存パッケージの取得（初回のみ）→ サーバー起動 → ブラウザ表示まで自動で行う。
終了するときは、開いたターミナルで `Control + C`。

### 方法B: コマンド

```bash
npm run dev
```

表示された `http://localhost:5173/` をブラウザで開く。

> **`index.html` をダブルクリックしても動かない。**
> JSX の変換とライブラリの解決を Vite が行っているため。
> 直接開いた場合は、その旨と起動手順が画面に表示される。

---

## 8. 動作確認

上から順に試して、すべて期待どおりなら構築完了。

| # | 操作 | 期待する結果 |
|---|---|---|
| 1 | `http://localhost:5173/` を開く | ログイン画面が出る（未ログインのため） |
| 2 | 「会員登録」から登録する | 物件一覧に遷移する |
| 3 | 「＋ 物件を登録」から1件登録 | 一覧の先頭にカードが増える |
| 4 | カードの「編集」で家賃を変更 | カードの表示が変わる |
| 5 | カードの「削除」 | 確認ダイアログの後、カードが消える |
| 6 | ブラウザをリロード | ログイン状態と物件が保たれる |
| 7 | 「ログアウト」 | ログイン画面に戻る |
| 8 | ログアウト後に `/` を開く | ログイン画面にリダイレクトされる |

### RLS の確認（重要）

別のメールアドレスでもう1アカウント作り、**先のユーザーが登録した物件が見えないこと**を確認する。
見えてしまう場合は RLS が効いていないので、5章の SQL が実行できているか確認する。


## 10. Vercel への公開

1. Vercel にログインし、**Add New → Project** から GitHub の `JWT_DEV` を Import
2. Framework は **Vite** として自動認識される（ビルド `npm run build` / 出力 `dist`）
3. **Settings → Environment Variables** に次の2つを登録する

   | 名前 | 値 |
   |---|---|
   | `VITE_SUPABASE_URL` | Supabase の Project URL |
   | `VITE_SUPABASE_PUBLISHABLE_KEY` | Supabase の Publishable key |

4. Deploy を実行する

補足:

- **`VITE_` の変数はビルド時に JS へ埋め込まれる。** 値を変えたら再デプロイしないと反映されない
- ルーティング設定は `vercel.json` に含まれている（全URLを `index.html` に返す）。
  これが無いと `/login` を直接開いたときに 404 になる
- 環境変数は `vercel.json` に書かない。ダッシュボードで設定する

## 11. トラブルシューティング

実際に遭遇したものを含む。

| 症状 | 原因 | 対処 |
|---|---|---|
| `index.html` をダブルクリックしても真っ白 | Vite 構成のため直接開けない | `起動.command` か `npm run dev` で起動する |
| 「接続情報がひな形の値のままです」 | `.env` が未設定 | 6章のとおり実際の値を入れて**再起動** |
| 「Supabase に接続できませんでした」 | URLの誤り／サーバー未再起動／プロジェクト停止／ネット未接続 | URLを確認し、開発サーバーを再起動する |
| 「物件テーブルがまだありません」 | `schema.sql` が未実行 | 5章を実行する |
| 「メールアドレスまたはパスワードが違います」 | 入力誤り、または未登録 | 会員登録から行う |
| 会員登録後にログインできない | Confirm email がオン | 確認メールのリンクを開く。または 4.2 でオフにする |
| 他人の物件が見えてしまう | RLS が無効、またはポリシー未設定 | 5章の SQL を再実行する |
| Vercel で `/login` が 404 | `vercel.json` が反映されていない | ファイルの存在を確認し、再デプロイする |
| Vercel で「ひな形の値のまま」と出る | 環境変数が未設定、または設定後に再デプロイしていない | 10章の3〜4を実施する |
| `.env` を変えたのに反映されない | ビルド時に埋め込まれる仕様 | 開発サーバーを再起動／本番は再デプロイ |
